Introduction to PlanX

PlanX — Urban Analytics Studio is a comprehensive geospatial analysis platform delivered as a QGIS Processing provider. Its 69 algorithms span the full urban-planning workflow: from understanding the existing city (network analysis, morphology, microclimate) through diagnosing problems (equity, accessibility, walkability) to designing and evaluating interventions (optimization, growth simulation, scenario comparison).

Architecture

PlanX follows a strict three-layer architecture:

  1. Algorithm layer (algorithms/alg_*.py) — thin QGIS Processing wrappers that define parameters, validate inputs, and format outputs. They contain no analytical logic.
  2. Engine layer (engine/*.py) — pure NumPy/SciPy modules that implement every method. They contain no QGIS imports and can be tested, profiled, and reasoned about independently.
  3. Plugin shell (planx.py, provider.py, studio_dock.py) — the QGIS integration surface: menus, docks, the tool browser, and the dashboard.

This separation means the mathematics described in this manual corresponds directly to the NumPy implementation in engine/ — what you read here is what runs.

Design principles

  • No external solvers. Every method runs inside the plugin using only NumPy (and optionally SciPy for sparse-matrix acceleration, with an identical pure-Python fallback). No web services, no licensed libraries, no cloud dependencies.
  • Deterministic. Given the same inputs and version, every algorithm produces identical outputs. Random seeds are fixed; tie-breaking is lexicographic.
  • Screening, not compliance. The environmental modules (noise, air quality, solar) are professional screening tools — they use the standard engineering formulas but are not a substitute for detailed environmental impact assessment by a licensed professional.

1. Network Analysis

The Network Analysis group provides the foundational graph infrastructure for the entire PlanX platform. Streets are modelled as an undirected primal graph where junctions are nodes and street segments are edges weighted by length (or a user-specified cost field). On this graph, the group builds the six classic transport-network queries: preparation (topological cleaning and node assignment), origin–destination cost matrices and routes, service areas (isochrones), nearest-facility allocation, and link criticality screening.

All six tools share a single Dijkstra engine (engine/paths.py) that uses scipy.sparse.csgraph when available and a pure-Python heapq kernel otherwise, with identical results asserted by unit tests. The engine tracks predecessor nodes and edge identifiers through the shortest-path tree, enabling full route-geometry reconstruction — not just costs.

Prepare Network

Processing ID: planx:preparenetwork

Overview

Converts raw street centreline layers into a topologically clean, routable network graph. This is the mandatory first step before any other network tool in PlanX: it snaps endpoints, assigns node IDs, computes edge lengths, and builds the adjacency structure that every downstream algorithm consumes. Without this preparation, crossing lines that appear connected visually will be treated as separate, unconnected edges — producing broken routes and nonsensical isochrones.

Theoretical Background

Transport network analysis inherits from graph theory: a road network is a primal graph $G = (V, E)$ where vertices $V$ represent intersections and edges $E$ represent street segments. The critical preprocessing step — sometimes called planarization or topology building — ensures that edges that cross in geographic space also share a node in the graph. This is the difference between a geometric line layer and a topological network.

The Prepare Network algorithm performs three operations:

  1. Endpoint snapping: endpoints within a tolerance are merged to a single junction node.
  2. Intersection detection: line segments that cross are split at the intersection point, and a shared node is inserted.
  3. Connectivity indexing: each segment is assigned an integer ID; adjacency lists map each node to its incident segments; edge lengths are computed in map units.

The method follows the standard GIS network-preparation pipeline described in Curtin (2007)✓✓✓ and implemented in libraries like NetworkX, igraph, and pgRouting — but implemented here in pure NumPy with an R-tree spatial index for performance.

Mathematical Formulation

Given a set of $m$ polylines $\{P_1, \ldots, P_m\}$ where each polyline is a sequence of coordinate pairs $P_i = \{(x_1, y_1), \ldots, (x_{k_i}, y_{k_i})\}$, the algorithm constructs:

Node set $V$ — unique spatial locations after snapping. Two endpoints $p, q$ are snapped together when:

$$\|p - q\|_2 \leq \varepsilon \tag{3}$$

where $\varepsilon$ is the snapping tolerance (default: 1.0 map unit).

Edge set $E$ — the polyline segments between consecutive nodes after intersection splitting. Each edge $e = (u, v)$ carries a weight:

$$w(e) = \ell_e \quad \text{or} \quad w(e) = f_{\text{cost}}(e) \tag{2}$$

where $\ell_e$ is the Euclidean length of the segment in map units, computed as the sum of distances between consecutive vertices:

$$\ell_e = \sum_{t=1}^{k-1} \sqrt{(x_{t+1} - x_t)^2 + (y_{t+1} - y_t)^2} \tag{1}$$

Adjacency — the compressed sparse row (CSR) representation $(indptr, indices, data)$ where $data[j]$ is the weight of the edge from node $i$ to node $indices[j]$, and $indptr[i]$ marks the start of the adjacency for node $i$.

2. Centrality & Space Syntax

This group quantifies the structural position of every street segment within the network — how central or peripheral it is, how much through-movement it attracts, and how easily it can be reached. The two tools are complementary: Network Centrality works on the primal graph with metric (Euclidean/length) costs, computing the four canonical centrality measures — closeness, betweenness, straightness, and eigenvector. Space Syntax works on the segment dual graph with angular costs (turn degree ÷ 90), computing the Hillier space-syntax measures of angular integration (to-movement potential) and angular choice (through-movement potential), including the size-normalised NACH and NAIN indices.

Taken together, these two tools provide the configurational diagnosis of a street network — the single most influential analysis in the PlanX suite for master-plan evaluation, because street configuration, once built, persists for centuries.

Network Centrality

Processing ID: planx:networkcentrality

Overview

Computes four classic graph-centrality indices for every node in a prepared street network: closeness (how near a node is to all others), betweenness (how many shortest paths pass through a node), straightness (how direct routes from a node are, comparing Euclidean to network distance), and eigenvector centrality (how connected a node is to other well-connected nodes, via power iteration). Each measure can be computed at multiple metric radii to separate local from global structure.

The tool uses Brandes' (2001) $O(nm + n^2 \log n)$ algorithm for betweenness with radius limiting and optional source sampling for large networks. Closeness follows the Wasserman–Faust normalisation so that values are comparable across networks of different sizes.

Theoretical Background

Centrality is one of the oldest and most studied concepts in network science, with roots in Bavelas (1948) and Freeman (1977). In urban networks, centrality measures correlate strongly with land value, retail location, pedestrian flows, and traffic volumes (Porta et al., 2006; Sevtsuk & Mekonnen, 2012).

Four canonical measures are computed:

  • Closeness centrality — the inverse of the mean shortest-path distance from a node to all others reachable within the radius. Wasserman–Faust normalisation scales it by $(N_r - 1)/(N - 1)$ where $N_r$ is the number of nodes reached, so a node that reaches every other node in one step scores 1.0.
  • Betweenness centrality — the fraction of all shortest paths between node pairs that pass through the node. Brandes (2001) provides the $O(nm)$ algorithm that accumulates pair-dependencies in a single backward pass per source.
  • Straightness centrality — the mean ratio of Euclidean (straight-line) distance to network distance for all pairs originating at the node. A node with straight radial routes scores high; a node on a winding cul-de-sac scores low.
  • Eigenvector centrality — the principal eigenvector of the adjacency matrix, computed by power iteration on $A + I$ (adding the identity prevents oscillation on bipartite graphs). A node is central if its neighbours are central (Bonacich, 1972).

Mathematical Formulation

Closeness (Wasserman–Faust):

$$C_C(i) = \frac{N_r(i) - 1}{N - 1} \cdot \frac{N_r(i) - 1}{\sum_{j \in V_r(i)} d(i, j)} \tag{4}$$

where $d(i,j)$ is the shortest-path distance, $V_r(i)$ is the set of nodes reachable from $i$ within radius $r$, and $N_r(i) = |V_r(i)|$. The first factor is the Wasserman–Faust correction for partial reachability; the second is the raw closeness (inverse mean distance).

Betweenness (Brandes, 2001):

$$C_B(v) = \sum_{\substack{s,t \in V \\ s \neq v \neq t \\ d(s,t) \leq r}} \frac{\sigma_{st}(v)}{\sigma_{st}} \tag{3}$$

where $\sigma_{st}$ is the number of shortest paths from $s$ to $t$, and $\sigma_{st}(v)$ is the number of those paths that pass through $v$.

Straightness:

$$C_S(i) = \frac{1}{N_r(i) - 1} \sum_{j \in V_r(i),\, j \neq i} \frac{\|p_i - p_j\|_2}{d(i, j)} \tag{2}$$

Eigenvector centrality:

$$C_E(i) = \frac{1}{\lambda} \sum_{j \in \mathcal{N}(i)} C_E(j) \tag{1}$$

where $\lambda$ is the largest eigenvalue of the adjacency matrix $A + I$, and $\mathcal{N}(i)$ is the set of neighbours of node $i$. The power iteration converges when $\|x^{(k+1)} - x^{(k)}\|_\infty < 10^{-6}$.

Symbolic Representation

Map betweenness with a graduated renderer using a sequential multi-hue ramp (Viridis or Inferno) in natural-breaks classification (5–7 classes). Closeness benefits from the same treatment. Straightness works well with a diverging ramp (RdYlGn) centred at the median. Eigenvector centrality is best visualised with quantile classification (5 classes) to expose the rank structure — the top quintile marks the spatial core. Always set the minimum symbol size to 0.5 mm and scale to 3 mm at maximum, with 30–50% opacity to handle overplotting in dense areas.

Interpretation Guide

The four measures capture different dimensions of "being central":

  • Closeness highlights accessibility hubs — the geometric centre of the network. High-closeness nodes are efficient origins for services (fire stations, distribution centres).
  • Betweenness highlights movement corridors — streets that lie on many shortest paths. High-betweenness segments carry heavy through-traffic and are natural retail high streets, but also suffer from severance and pollution at extreme values.
  • Straightness measures route directness. Low straightness means residents must travel much further than the crow flies — a tax on time and fuel. Cul-de-sac suburbs typically show low straightness.
  • Eigenvector centrality identifies the "core of the core" — nodes connected to other highly central nodes. This is the city's structural backbone and the most resilient part of the network.

Cross-reference with Space Syntax: betweenness correlates with angular choice (NACH), closeness with angular integration (NAIN). Discrepancies between the metric and angular pictures reveal where the geometry of the grid matters beyond simple distance — a long straight boulevard may score high on metric closeness but low on angular integration if it turns sharply relative to the surrounding grid.

Space Syntax (Segment Angular Analysis)

Processing ID: planx:spacesyntax

Overview

Performs segment angular analysis — the modern space syntax workflow — directly on road centreline segments. Unlike traditional axial-map space syntax, this method uses the segment dual graph: each street segment between junctions becomes a node, and connections between segments carry an angular cost equal to the turn angle in degrees divided by 90 (straight = 0, right angle = 1). Shortest paths minimise this angular cost, effectively finding the least-turning routes through the city.

For every specified radius, the tool computes six measures per segment: NC (node count reached), TD (angular total depth), MD (angular mean depth), NAIN (normalised angular integration — to-movement potential), CH (raw angular choice — through-movement count), and NACH (normalised angular choice). The normalised measures follow Hillier, Yang & Turner (2012) and are size-independent, enabling comparison across cities of different sizes.

Theoretical Background

Space syntax theory, pioneered by Bill Hillier and colleagues at University College London since the 1970s, posits that the spatial configuration of a city — the pattern of connections and barriers in its street network — is the primary generator of movement, land use, and social encounters. This is the "theory of natural movement" (Hillier et al., 1993): the grid itself, more than any land-use designation, determines where people walk, drive, and gather.

The evolution of the method has three generations:

  1. Axial analysis (1970s–1990s): the fewest and longest lines of sight covering all open space, connected at intersections. Hand-drawn, subjective, and resolution-dependent.
  2. Segment angular analysis (Turner, 2001): the axial map is broken into segments between intersections, and connections are weighted by turn angle. This removes the subjectivity of axial drawing and captures the cognitive reality that people prefer straight routes.
  3. Normalised measures — NACH and NAIN (Hillier, Yang & Turner, 2012): the raw measures (integration, choice) are inherently dependent on system size — a larger network will have longer paths and higher choice counts. NACH and NAIN normalise away size, enabling the first rigorous numerical comparison of cities worldwide.

The 50-city comparative study (Hillier, Yang & Turner, 2012) established benchmarks: city-mean NACH ranges from ~0.7 (disconnected sprawl) to ~1.1 (dense grids); maximum NACH ranges from ~1.2 to ~1.6. The foreground network (top 10–20% of NACH) carries most through-movement; the background network (the rest) is the residential fabric. The permeability of the background — how easily it feeds into the foreground — determines whether a neighbourhood is integrated into city life or isolated from it.

Mathematical Formulation

Segment dual graph. Given $n$ street segments with coordinates, the segment graph is built by the engine (engine/graphs.py). Two segments $(u, v)$ are adjacent if they share an endpoint. The angular cost of turning from segment $u$ to segment $v$ is:

$$c(u, v) = \frac{\theta_{uv}}{90^\circ} \tag{6}$$

where $\theta_{uv} \in [0^\circ, 180^\circ]$ is the deflection angle between the last direction vector of $u$ and the first direction vector of $v$ (taking the smaller angle, since the graph is undirected). Internal polyline curvature within each segment is also accumulated — the angular cost along a segment equals the sum of turn angles between its consecutive sub-segments divided by 90°.

Angular shortest paths. For each source segment $s$, a modified Dijkstra algorithm computes the minimum angular-cost path to every other segment $t$ within metric radius $r$ (if specified). The result is the angular distance matrix $d_{ang}(s, t)$.

Angular total depth (TD) and node count (NC):

$$TD(s) = \sum_{t \in V_r(s)} d_{ang}(s, t) \qquad NC(s) = |V_r(s)| \tag{5}$$

Angular mean depth (MD):

$$MD(s) = \frac{TD(s)}{\max(NC(s) - 1, 1)} \tag{4}$$

Angular choice (CH) — raw betweenness:

$$CH(s) = \sum_{u \neq s \neq v} \frac{\sigma_{uv}^{ang}(s)}{\sigma_{uv}^{ang}} \tag{3}$$

where $\sigma_{uv}^{ang}$ is the number of least-angular-cost paths between $u$ and $v$, and $\sigma_{uv}^{ang}(s)$ counts those passing through $s$. Since the graph is undirected, each unordered pair $(u,v)$ is counted twice; the engine divides by 2 to obtain pair-based choice.

NAIN — Normalised Angular INtegration (to-movement potential):

$$NAIN(s) = \frac{(NC(s) + 2)^{1.2}}{TD(s) + 2} \tag{2}$$

The constants +2 in numerator and denominator prevent division by zero for isolated segments. The exponent 1.2 was calibrated by Hillier, Yang & Turner (2012) to maximise correlation with observed movement rates across 50 cities. High NAIN = easy to arrive at — the segment is a destination magnet.

NACH — Normalised Angular CHoice (through-movement potential):

$$NACH(s) = \frac{\log_{10}(CH(s) + 1)}{\log_{10}(TD(s) + 3)} \tag{1}$$

The constants +1 and +3 keep the ratio real and finite (choice can be zero; total depth is at least 1). High NACH = heavily used as a through route — the segment is in the foreground movement grid.

Both NACH and NAIN are dimensionless and approximately invariant to system size — a segment in a small town and a segment in a metropolis with the same configurational role will have similar NACH/NAIN values.

Symbolic Representation

NACH and NAIN are the two primary map products.

  • NACH map: Graduated renderer, sequential multi-hue (Viridis or Plasma), quantile classification with 7–10 classes. The top 10–20% of values (the foreground) should be visually dominant — thicken these lines to 0.6–0.8 mm; background lines at 0.2 mm. The quantile classification is critical because NACH is still somewhat right-skewed; natural breaks will lump most segments into the bottom class.
  • NAIN map: Same approach, but use a warm sequential ramp (OrRd or YlOrRd) — integration reads as "heat" (activity concentration). The top 10% are the city's cores; expect them to align with historic centres and high streets.
  • Joint NACH+NAIN interpretation map: Bivariate colour scheme — or, more practically, two side-by-side map panels with synchronised extents. QGIS map themes make this straightforward.
  • Legend format: Two decimal places (e.g. "0.95 – 1.12"). Do not include unit symbols — NACH and NAIN are dimensionless.

OD Cost Matrix

Processing ID: planx:odmatrix

Overview

Computes the full origin–destination cost matrix over the street network using the embedded Dijkstra engine — no external routing plugin or server. For every origin–destination pair, it reports the shortest-path network cost, the straight-line (Euclidean) distance, and the detour ratio (network ÷ Euclidean). Optional desire lines render the matrix as straight-line glyphs styled by cost or detour.

This is the foundational input for gravity models, accessibility studies, facility siting, and any analysis that needs to know "how far is A from B on the real network."

Theoretical Background

The OD cost matrix is the most basic product of a transportation network model: it answers the question "how far apart are these places?" for every pair of interest. The concept originates in traffic analysis zone (TAZ) planning, where trip distribution models (gravity, intervening opportunities) require a cost matrix as their impedance input (Ortúzar & Willumsen, 2011). In GIS, the matrix is the output of a many-to-many shortest-path computation.

The detour ratio — network distance divided by straight-line distance — is a simple but powerful diagnostic. In a perfect grid with no barriers, detour ratios cluster around 1.2–1.3 (the "Manhattan metric" factor of $\sqrt{2}$ vs. the diagonal, averaged over random orientations). Values above 1.4 signal that the network forces a long way around: a river with few bridges, a railway corridor, a superblock perimeter, or a missing street link. The detour ratio thus doubles as a barrier-effect index — the single OD pair with the highest detour often pinpoints exactly where a new pedestrian bridge or street connection would deliver the highest accessibility return on investment.

Mathematical Formulation

Network cost. For each origin $i$ and destination $j$, the engine computes the shortest-path distance $d_{net}(i,j)$ by Dijkstra's algorithm on the primal graph $G = (V, E)$ with edge weights $w(e)$ (geometric length or a user-specified cost field):

$$d_{net}(i,j) = \min_{path(i \to j)} \sum_{e \in path} w(e) \tag{3}$$

Euclidean distance (as the crow flies):

$$d_{euc}(i,j) = \sqrt{(x_i - x_j)^2 + (y_i - y_j)^2} \tag{2}$$

Detour ratio:

$$detour(i,j) = \frac{d_{net}(i,j)}{d_{euc}(i,j)} \tag{1}$$

The engine uses SciPy's csgraph.dijkstra for the sparse-matrix fast path when available, falling back to a pure-Python heapq implementation with identical results. Points snap to their nearest network node. The many-to-many computation runs Dijkstra once per origin, reusing the full shortest-path tree to reach all destinations — a $O(m \cdot (n \log n + e))$ operation where $m$ is the number of origins.

OD Routes (Shortest Paths)

Processing ID: planx:odroutes

Overview

Computes actual shortest-path route geometries over the street network from origins to destinations. Unlike the OD Cost Matrix (which returns only costs), this tool reconstructs the precise sequence of street segments traversed — turn by turn — for every origin–destination pair. Each route includes the network cost, Euclidean distance, detour ratio, and the number of edges traversed. Optional straight desire lines complement the route geometries.

The tool supports k-nearest destination filtering and a cost cutoff to keep output manageable for large OD sets.

Theoretical Background

Route reconstruction from a shortest-path tree is the standard predecessor-tracking technique: during Dijkstra's algorithm, each node records which predecessor node and which edge were used to reach it with the minimum cost. After the tree is built, a path from source $s$ to target $t$ is reconstructed by walking backwards from $t$ through the predecessor chain to $s$, collecting the edge IDs along the way. The edge geometries are then assembled in travel order, with each polyline oriented correctly (from the closer endpoint to the farther one).

The k-nearest filter uses a stable sort on distance to select the $k$ closest destinations per origin. Ties are broken by the destination's index order, ensuring deterministic results.

Mathematical Formulation

Shortest-path tree. For each origin $s$, Dijkstra's algorithm computes:

  • $dist[t]$ — minimum cost from $s$ to every node $t$
  • $pred\_node[t]$ — the predecessor node on the shortest path to $t$
  • $pred\_edge[t]$ — the edge ID connecting $pred\_node[t]$ to $t$

Path reconstruction. Starting from target node $t$:

  1. Push edge $pred\_edge[t]$ onto the edge list
  2. Set $t \leftarrow pred\_node[t]$
  3. Repeat until $t = s$ (source reached) or predecessor is invalid
  4. Reverse the edge list to obtain travel order from origin to destination

Route geometry assembly. For each edge in the ordered list, the polyline coordinates are oriented so the first vertex is closest to the current position. Consecutive edges share the junction node, producing a contiguous linestring.

$$length\_m = \sum_{e \in route} \ell_e \tag{1}$$

Service Areas (Isochrones)

Processing ID: planx:serviceareas

Overview

Computes true network catchments around facilities with exact partial-edge reach: walking budgets end mid-street, so streets are trimmed at the precise point where the cost budget runs out. For each break distance, the tool produces trimmed street pieces (coloured by cost band), service area polygons (buffer, concave hull, or convex hull), and straight-line circles for comparison. The pedshed ratio (network catchment area ÷ circle area) is the classic measure of how much the street layout shrinks the reach promised by a given radius.

Theoretical Background

Service area (isochrone) analysis is the spatial implementation of catchment-based planning standards: a regulation states that every residence must be within 500 m of a park, 800 m of a primary school, or 400 m of a bus stop. The straight-line (crow-flies) buffer that most GIS users draw to check compliance is systematically optimistic — it ignores the street network entirely. The difference between the circle and the true network catchment is the pedshed ratio (Porta & Renne, 2005; also known as the "network-to-circle" or "catchment efficiency" ratio).

The partial-edge technique is critical for accuracy at walking-scale budgets (≤ 1 km): a budget of 500 m that stops at the nearest junction may overshoot or undershoot by up to a full block length (~80–150 m), a 15–30% error. Exact partial-edge trimming interpolates the budget point along each edge proportionally, eliminating this error entirely (Curtin, 2007).

Mathematical Formulation

Multi-source Dijkstra with entry costs. Each facility $f$ enters the network at its nearest point on the nearest edge $(e_f, t_f)$ where $t_f \in [0,1]$ is the position along the edge. Two node-offset entries are created for the edge's endpoints with the approach cost added:

$$cost_{entry}(a) = d_{snap} + t_f \cdot \ell_{e_f} \tag{4}$$ $$cost_{entry}(b) = d_{snap} + (1 - t_f) \cdot \ell_{e_f} \tag{3}$$

where $d_{snap}$ is the straight-line snap distance (added to the budget when cost is length). Dijkstra runs once from all facility entries simultaneously, producing per-node costs and winning-facility labels.

Partial-edge reach intervals. For an edge $(u, v)$ with cost $\ell$ and node costs $d_u, d_v$, the reachable portion within budget $B$ is the interval $[t_{min}, t_{max}]$ where the interpolated cost at position $t$ is ≤ $B$:

$$cost(t) = \min(d_u + t\ell,\; d_v + (1-t)\ell) \leq B \tag{2}$$

Pedshed ratio:

$$pedshed = \frac{A_{catchment}}{A_{circle}} = \frac{\text{network catchment area}}{\pi \cdot B^2} \tag{1}$$

Pedshed ≥ 0.6 = well-connected grid; 0.4–0.6 = average; < 0.4 = poor — the network delivers less than half the promised radius.

Nearest Facility Allocation

Processing ID: planx:nearestfacility

Overview

Assigns every demand point (building, household, parcel centroid) to its nearest facility over the street network and reports each facility's total load. A single multi-source Dijkstra run resolves all assignments at once — every demand point is simultaneously claimed by its closest facility. Outputs include the allocated demand layer (with assigned facility label and network cost), optional spider/allocation lines, reconstructed network-path routes, and a per-facility load summary with demand count, mean cost, and maximum cost.

Theoretical Background

Nearest-facility allocation solves the Voronoi problem on a network: instead of partitioning space into Euclidean regions (as a standard Thiessen/Voronoi diagram would), it partitions it by shortest-path distance. The de-facto catchment boundaries it produces — the lines where the nearest facility changes — rarely align with administrative boundaries or straight-line catchment circles. This is the fundamental insight of network-based accessibility planning: the street network, not the radius, determines who goes where (Talen & Anselin, 1998).

The multi-source Dijkstra technique (Dijkstra, 1959) is functionally equivalent to running the algorithm with a virtual super-source connected to all facility nodes with zero cost. All demand nodes are labelled with the facility that first reaches them. The approach is $O((n + f) \log n + e)$ where $f$ is the number of facilities.

Mathematical Formulation

Given $n$ demand locations and $f$ facility locations, each snapped to network nodes, the algorithm computes:

$$label(d) = \arg\min_{k \in \{1,\ldots,f\}} d_{net}(k, d) \tag{5}$$ $$cost(d) = \min_{k \in \{1,\ldots,f\}} d_{net}(k, d) \tag{4}$$

where $d_{net}(k,d)$ is the shortest-path distance from facility $k$ to demand $d$ on the graph. If multiple facilities share a node, the first one in the input order wins — assignments are deterministic.

Facility load:

$$load(k) = |\{d : label(d) = k\}| \tag{3}$$ $$mean\_cost(k) = \frac{1}{load(k)} \sum_{d: label(d)=k} cost(d) \tag{2}$$ $$max\_cost(k) = \max_{d: label(d)=k} cost(d) \tag{1}$$

Link Criticality (Network Robustness)

Processing ID: planx:linkcriticality

Overview

Ranks every street segment by how badly the network would suffer if that segment were lost — the road-network vulnerability view based on the Network Robustness Index (Scott et al., 2006; Jenelius et al., 2006). For a given origin–destination demand set, the tool first routes every pair on the intact network, then removes each segment in turn and re-routes, reporting the extra travel cost each removal forces plus any demand it cuts off entirely. Only segments that carry at least one shortest path are re-tested — the rest cannot change any route and score zero, which prunes the computation significantly.

Theoretical Background

Network robustness analysis emerged from transportation engineering's need to identify critical infrastructure — bridges, tunnels, and arterial segments whose failure (due to earthquake, flood, accident, or targeted attack) would disproportionately cripple the network. Unlike betweenness centrality, which counts how many shortest paths use a segment without considering what happens when it is removed, link criticality measures the consequence of removal: the additional travel cost imposed on the OD demand (the detour bill) and the number of OD pairs that become completely disconnected.

The Network Robustness Index (Scott et al., 2006) formalises this:

$$NRI(e) = \frac{\sum_{od} \left(d_{net}^{(e)}(o,d) - d_{net}(o,d)\right)}{\sum_{od} d_{net}(o,d)} \tag{4}$$

where $d_{net}(o,d)$ is the shortest-path cost in the intact network and $d_{net}^{(e)}(o,d)$ is the cost in the network with edge $e$ removed. The denominator normalises by total baseline cost, making NRI comparable across different demand scenarios and network sizes.

Edge removal is implemented efficiently as a CSR adjacency mask — the graph is not rebuilt for each edge. Instead, the removed edge's entries in the adjacency matrix are temporarily masked out, and Dijkstra runs on the masked matrix. Only edges with used_by > 0 (on at least one intact shortest path) are tested, which typically prunes 60–90% of edges in urban networks with high redundancy.

Mathematical Formulation

Baseline routing. For every OD pair $(o,d)$ in the demand set, compute $d_{net}(o,d)$ on the intact graph $G$. The base total is:

$$T_{base} = \sum_{o,d} d_{net}(o,d) \tag{3}$$

An edge $e$ is a candidate if it lies on at least one intact shortest path: $used\_by(e) = |\{(o,d) : e \in path(o,d)\}| > 0$.

Removal test. For each candidate edge $e$, route all OD pairs on $G \setminus \{e\}$:

$$extra\_cost(e) = \sum_{o,d} \max(0,\; d_{net}^{(e)}(o,d) - d_{net}(o,d)) \tag{2}$$

Note: removal can only lengthen paths, so $extra\_cost(e) \geq 0$. If the removal severs an OD pair entirely, $d_{net}^{(e)}(o,d)$ is infinite and the pair contributes to $n\_disconnected(e)$.

Criticality (NRI):

$$criticality(e) = \frac{extra\_cost(e)}{T_{base}} \tag{1}$$

Criticality is dimensionless, typically in $[0, 0.1]$ — losing a single segment rarely adds more than 10% to total travel, though extreme values occur for bridges and single-access connectors.

10. Walkability

The Walkability group translates the walkable-city agenda into four interconnected GIS tools. Walkability Audit scores every street segment 0–100 using the classic Frank et al. (2010) ingredients: intersection density, land-use mix, destinations, block length, and slope — each normalised with documented breakpoints and combined with editable weights. Walkability Audit

Processing ID: planx:walkability

Overview

Scores every street segment 0–100 for walkability using five classic ingredients from the walkability-index literature: intersection density (connectivity), land-use mix (normalised Shannon entropy of buffer areas), destination counts (POIs within radius), block length (mean street-segment length as a block-size proxy), and slope (segment gradient from an optional DEM). Each ingredient is normalised 0–100 with documented breakpoints; missing inputs are renormalised away so the tool degrades gracefully with partial data. The output is the definitive "existing conditions" exhibit for a pedestrian master plan.

Theoretical Background

The walkability index traces its lineage to urban planning's D-variables framework (Ewing & Cervero, 2010): Density, Diversity (land-use mix), Design (street connectivity), Destination accessibility, and Distance to transit. Frank et al. (2010) operationalised four of these for the Neighborhood Quality of Life Study. PlanX adapts this to the street-segment level — walkability is fundamentally a network property: a street is walkable not in isolation but by virtue of what it connects to. Breakpoints default to a comfortably walkable European urban fabric: 120 junctions/km², 80 m block length, 25 POIs, and 0% slope all score 100.

Mathematical Formulation

Intersection density. Junctions (degree ≥ 3) counted within radius $r$ of each segment midpoint:

$$int\_km2(s) = \frac{|\{j : \|p_j - m_s\| \leq r\}|}{\pi r^2 / 10^6} \qquad s\_inters(s) = 100 \cdot \min(1, int\_km2(s) / 120) \tag{2}$$

Land-use mix. Normalised Shannon entropy of buffer land-use areas:

$$mix(s) = \frac{-\sum_c p_c \ln p_c}{\ln N_{cat}} \in [0,1] \qquad s\_mix(s) = 100 \cdot mix(s) \tag{1}$$

Destinations. POI count within radius: $s\_dest(s) = 100 \cdot \min(1, n\_pois(s) / 25)$.

Block length (smaller-is-better): $s\_block(s) = 100 \cdot \max(0, \min(1, (400 - blk\_len(s)) / (400 - 80)))$.

Slope: $slope\_pct(s) = |z_{end} - z_{start}| / \ell_s \cdot 100$, then $s\_slope(s) = 100 \cdot \max(0, 1 - slope\_pct(s) / 10)$.

Composite: $walk\_score(s) = \sum w_c \cdot s_c(s) / \sum w_c$ over available components, with missing weights renormalised.

Overview

Street Environment Comfort

Processing ID: planx:streetcomfort

Overview

Scores street segments 0–100 by aggregating kernel-density estimates of comfort assets (trees, benches, lighting) and barriers (potholes, blank walls), plus optional raster factors (sunlight, heat, noise). Pedestrian Route Quality

Processing ID: planx:routequality

Overview

Routes pedestrians over quality-weighted streets and reports what the walk is actually like. Each segment's cost: $\ell_e \cdot (1 + p \cdot (100 - score)/100)$. With penalty $p=1$, a score-0 street counts double. For each OD pair: detour ratio (price of pleasantness), length-weighted mean walk score, and share of route on low-scoring segments. Pairing: nearest destination or all pairs.

Interpretation Guide

detour ≈ 1.0: direct route already pleasant. detour ≥ 1.3: direct route so poor it's worth 30% more distance to escape — a strong indictment. low_share > 0.3 with detour ≈ 1.0: trapped — there IS no better alternative. This combination identifies missing-link investments better than either metric alone. Run home-to-school pairs and rank by low_share for Safe Routes to School prioritisation.

Street Network Morphology

Processing ID: planx:streetnetworkmorphology

Overview

Profiles a street network's structure in one pass: orientation entropy and order (Boeing, 2019), three meshedness indices (alpha, beta, gamma), junction typology (cul-de-sac, continuation, intersection), and a full summary table. Ideal for comparing neighbourhoods or tracking plan iterations.

Mathematical Formulation

Orientation entropy: $H = -\sum_b p_b \ln p_b$ on 36-bin bearing histogram weighted by edge length. Order: $\phi = 1 - ((H-H_g)/(H_{max}-H_g))^2$ where $H_{max}=\ln(36)$, $H_g=\ln(4)$. $\phi = 1$ = perfect grid; $\phi \approx 0$ = organic/random.

Interpretation Guide

$\phi$ > 0.7: planned grid fabric; 0.1–0.3: organic/topography-driven. A jump in $\phi$ at a district boundary = two planning eras meeting. $\alpha$ < 0.1: tree-like network, fragile; 0.2+: well-meshed. Cul-de-sac ratio + intersection density: the sprawl signature in two numbers.

Sky View Factor (DSM)

Processing ID: planx:skyviewfactor

Overview

Computes SVF — the fraction of visible sky hemisphere from each ground cell. SVF = 1.0 (open field) to ~0.4 (deep urban canyon). The single most important geometric control on urban microclimate: governs longwave radiation loss (night cooling, UHI intensity), daytime solar access, and daylight availability.

Mathematical Formulation

For $N$ azimuth directions, scan outward to find max horizon elevation $\beta_i$: $\text{SVF} = 1 - \frac{1}{N}\sum \sin^2(\beta_i)$, using $\sin^2(\arctan t) = t^2/(1+t^2)$. Clipped to [0,1]. Johnson & Watson (1984) method.

Interpretation Guide

SVF > 0.9: open field — cools fast at night, bakes by day. Good for PV, poor for pedestrian comfort without shade. SVF 0.4–0.6: dense urban fabric, canyons forming. SVF < 0.4: deep canyon — traps daytime heat, blocks nocturnal cooling. Continuous low-SVF corridors = systematic obstruction. Combine with Heat Risk Grid and Frontal Area Index for comprehensive UHI screening.

Academic References

Oke, T.R. (1981). "Canyon geometry and the nocturnal urban heat island." Journal of Climatology, 1(3), 237–254. DOI: 10.1002/joc.3370010304 ✓✓✓

Johnson, G.T. & Watson, I.D. (1984). "The Determination of View-Factors in Urban Canyons." Journal of Climate and Applied Meteorology, 23(2), 329–335. DOI: 10.1175/1520-0450(1984)023<0329:TDOVFI>2.0.CO;2 ✓✓✓

Frontal Area Index

Processing ID: planx:frontalareaindex

Overview

Computes $\lambda_f$ (frontal area index) and $\lambda_p$ (plan area index) per grid cell — the standard urban roughness parameters for wind permeability and ventilation corridor studies (Grimmond & Oke, 1999). For a given wind direction, $\lambda_f$ measures wind-facing facade area per unit ground area.

Mathematical Formulation

For wind direction $\theta$ (bearing wind comes FROM), building $i$ with height $h_i$: $w_{proj} = \max(p_x\cos\theta - p_y\sin\theta) - \min(p_x\cos\theta - p_y\sin\theta)$, $F_i = w_{proj} \cdot h_i$. Per cell: $\lambda_f = \sum F_i \cdot A_{i \cap c} / (A_i^{fp} \cdot A_{cell})$.

Interpretation Guide

$\lambda_f$ < 0.1: open fetch. 0.1–0.3: moderate roughness. > 0.3: strong wind blockage — these cells warrant ventilation corridor protection. Run with prevailing SUMMER breeze direction. Compare $\lambda_f$ and $\lambda_p$: high $\lambda_p$ + low $\lambda_f$ = dense-but-low (shopping strips); low $\lambda_p$ + high $\lambda_f$ = porous-but-tall (towers). These behave completely differently for wind and heat.

Academic References

Grimmond, C.S.B. & Oke, T.R. (1999). "Aerodynamic Properties of Urban Areas Derived from Analysis of Surface Form." Journal of Applied Meteorology, 38(9), 1262–1292. DOI: 10.1175/1520-0450(1999)038<1262:APOUAD>2.0.CO;2 ✓✓✓

Sun Hours (DSM)

Processing ID: planx:sunhours

Overview

Computes hours of direct sunlight per DSM cell over one full day via repeated shadow casting at a fixed interval (default 30 min). The shadow-duration map that previously required batch-running Shadow Casting — now in a single tool.

Mathematical Formulation

$\text{hours}(x,y) = \frac{\Delta t}{60} \sum_{k: \alpha_k > 0} (1 - \text{shadow}_k(x,y))$. Site potential daylight (unobstructed) reported in log for comparison.

Interpretation Guide

Always read hours relative to potential daylight in the log. Common regulatory thresholds: ~2 hours direct sun on Dec 21 or Mar 21 for habitable rooms; 4–6 hours for playgrounds. Run both winter AND summer: winter shows where sunlight is missing; summer shows where shade is missing. Roofs with > 4–6 winter hours = good PV screening potential.

Solar Irradiation (DSM)

Processing ID: planx:solarirradiation

Overview

Computes clear-sky global solar irradiation per cell for a single day in kWh/m². Combines shadow-aware beam (direct) irradiance via ASHRAE clear-sky model with SVF-weighted isotropic diffuse (Masters, 2004). Screening-quality: correctly ranks roofs and spaces for relative solar potential.

Mathematical Formulation

ASHRAE clear-sky: $DNI = A \cdot \exp(-k/\sin\beta)$, $DHI = C \cdot DNI$, Beam horizontal = $DNI \cdot \sin\beta$. Per time step: sunlit cell gets beam + diffuse·SVF; shadowed cell gets only diffuse·SVF. Daily total: $\text{kWh/m}^2 = \frac{1}{1000}\sum E_{cell}^{(k)}$.

Interpretation Guide

Always read relative to the flat-ground reference in the log. A roof at 90% of reference = essentially unshaded; below ~70% = surroundings cost real yield. Clear-sky = every value is an upper bound (clouds remove 30–50%). For PV screening, run on winter dates (the binding season).

Academic References

Masters, G.M. (2004). Renewable and Efficient Electric Power Systems. Wiley. DOI: 10.1002/0471668826 ✓✓✓

Annual Solar Potential (DSM)

Processing ID: planx:annualsolar

Overview

Computes clear-sky global solar irradiation summed over a full year in kWh/m²/yr using the Klein (1977) monthly-average method: 12 representative days, each computed with the full shadow-aware + SVF-weighted model, scaled by days per month. Optional 12-band monthly raster output.

Mathematical Formulation

$E_{annual} = \sum_{m=1}^{12} \text{daily\_irradiation}(d_m) \times N_m$, using Klein's representative days (Jan 17, Feb 16, …, Dec 10).

Interpretation Guide

The ratio cell / flat-ground reference isolates what urban form does to solar access independent of climate. >0.9 = practically unobstructed roof; <0.7 = surroundings cost ≥30% of potential. Rank roofs by annual total, then open monthly bands of the shortlist for seasonal assessment. For PV estimation: multiply by usable roof area × system factor (0.75–0.85) × cloud correction (0.5–0.7).

Heat Island Risk Grid

Processing ID: planx:heatriskgrid

Overview

Screens for UHI risk on a regular grid using only building footprints, green areas, and optional water bodies — no satellite data needed. Each cell scored 0–100 from built fraction, mean building height, green fraction, and water fraction on a fixed scale (comparable between scenarios). Output includes risk score, four-class label, and component fractions.

Mathematical Formulation

$\text{raw} = w_{built}\cdot b + w_{height}\cdot\min(h/h_{ref},1) - w_{green}\cdot g - w_{water}\cdot w$. Mapped to 0–100 using fixed anchors (not data-driven). Risk classes: Low <25, Moderate 25–50, High 50–75, Very High ≥75.

Interpretation Guide

Score is relative, not °C. Read component fractions to choose the remedy: high built + low green → depave and plant; high height + low green → shade structures. The fixed scale means re-running after adding a park produces directly comparable numbers: "The park drops 14 cells out of Very High." Default weights: built 0.4, height 0.2, green 0.3, water 0.1.

Road Noise Screening

Processing ID: planx:noisescreening

Overview

Screening-quality road traffic noise grid using RLS-90-style emission and geometric spreading with optional building insertion loss. NOT a legal noise map. Road Emissions

Processing ID: planx:roademissions

Overview

Air Quality Screening

Processing ID: planx:airscreening

Overview

Screening-quality dispersion grid: road segments sampled as line-calibrated point sources, concentration index $\chi = \sum S_i / (u \cdot (d_i + d_0)^\alpha)$. Index is RELATIVE, not µg/m³. Top decile = hotspot list. Canyon-flagged segments are the first priority: moderate-traffic canyon can produce higher index than heavy-traffic open arterial. $\alpha$ controls spatial scale: 0.5 = broad plumes; 2.0 = concentrated near-source. Use $\alpha$ = 1.0 for street-level screening.

6. Plan Standards and QA

Land-Use Balance

Processing ID: planx:landusebalance

Overview

Computes per-capita land-use balance against configurable standards (e.g. green=10, education=4). For each land-use category: total area, m² per capita, required area, surplus/deficit, and compliance status. Standards match categories case-insensitively by keyword containment.

Mathematical Formulation

$m_c = A_c / P$ (per-capita provision), $R_c = s \cdot P$ (required), $B_c = A_c - R_c$ (balance). Status: "Meets standard" if $B_c \geq 0$, "Deficit" if $B_c < 0$, "No standard" if unmatched.

Interpretation Guide

Run with current AND horizon population. Categories flipping to "Deficit" identify the land reservations needed before demand materialises. "No standard" rows are warnings, not passes. City-wide averages hide spatial mismatch — pair with Facility Adequacy or Green Access to test reachability.

Facility Adequacy

Processing ID: planx:facilityadequacy

Overview

Evaluates facilities along two dimensions simultaneously: spatial accessibility (network catchment) and capacity (assigned population vs. capacity). Demand assigned to nearest facility within catchment; utilisation = assigned / capacity. Output: facility adequacy (with status) and demand coverage (covered/uncovered).

Interpretation Guide

Covered population share in the log is the headline pass/fail. Facilities with utilisation > 1 (Overloaded) = enough proximity, not enough capacity. "Unused" facilities with uncovered demand nearby = wrong location or network barrier. Uncovered demand: either beyond every catchment (build new) or inside a catchment whose facility is full (capacity problem).

Scenario Compare (A/B)

Processing ID: planx:scenariocompare

Overview

Composite score is RELATIVE to the compared set. Rank ties = genuinely undistinguishable alternatives. Check skipped metrics list (neutral/not-shared/constant) before trusting ranking.

8. Optimization

Five facility and land-use optimisation tools operating on the street network via an embedded engine — no external solvers. Two facility models (maximal coverage via greedy + p-median via Teitz-Bart substitution), one capacitated allocation with spill tracking, one multi-objective land-use allocator with compactness and adjacency terms, and a Pareto front tracer that maps the suitability-compactness trade-off.

Facility Location Optimizer

Processing ID: planx:facilitylocation

Overview

Selects the best sites for new facilities among candidates on the real street network. Two models: Maximal Coverage (greedy, each step picks the candidate covering the most uncovered demand within radius) and P-Median (greedy construction + Teitz-Bart vertex substitution to minimise population-weighted travel cost). Existing facilities are fixed; new sites complement them.

Interpretation Guide

Rank and gain tell the investment story: rank 1 = single best site; each "gain" = extra demand covered. When gain collapses (pick 4 adds a fraction of pick 1), that's the diminishing-returns point. Coverage chases the threshold (good for standards); p-median shortens everyone's average trip (good for daily services). Run both — sites picked by BOTH are robust.

Overview

9. Equity

Accessibility Equity (Gini / Theil)

Processing ID: planx:accessequity

Overview

Measures how fairly a per-unit value (access score, travel time) is distributed across population. Headline indices (population-weighted): Gini coefficient, Theil's T (additively decomposable into between/within-group), P90/P10, coefficient of variation, and access-poverty share. When a group field is provided (district, income), the between-share answers the environmental-justice question.

Mathematical Formulation

Weighted Gini: $G = \sum w_i(x_i \cdot W_i^{below} - S_i^{below}) / (W \cdot S)$ (O(n log n) sorted form). Theil: $T = \frac{1}{W}\sum w_i \cdot (x_i/\mu)\ln(x_i/\mu)$. Decomposition: $T = T_{between} + T_{within}$, where $T_{between} = \sum s_g \ln(\mu_g/\mu)$.

Interpretation Guide

Gini rules of thumb: <0.2 = evenly provided; 0.2–0.35 = normal urban unevenness; >0.4 = strongly concentrated. Always read WITH the mean — perfect equality at a miserable level is not a goal. Theil between-share: if 60% of inequality is BETWEEN groups, place-based investment fixes it; if most is WITHIN, district-level policy misses it. Projects raising the mean by serving already-good areas WORSEN these indices.

Academic References

Shorrocks, A.F. (1980). "The class of additively decomposable inequality measures." Econometrica, 48(3), 613–625. DOI: 10.2307/1913126 ✓✓✓

Inequality Curves (Lorenz & Atkinson)

Processing ID: planx:inequalitycurves

Overview

Draws the Lorenz curve (cumulative population vs. cumulative value share) and computes the Atkinson index at multiple inequality-aversion levels (ε = 0.5, 1, 2). Optional external rank field for concentration curve. Output: curve points table and inequality summary.

Mathematical Formulation

Lorenz: $P_k = \sum_{i=1}^k w_{(i)} / \sum w_i$, $L_k = \sum w_{(i)} x_{(i)} / \sum w_i x_i$. Atkinson: $\text{EDE} = (\sum w_i x_i^{1-\epsilon} / \sum w_i)^{1/(1-\epsilon)}$ for ε≠1, $A(\epsilon) = 1 - \text{EDE}/\mu$. Gini from Lorenz: $G = 1 - \sum (P_k - P_{k-1})(L_k + L_{k-1})$.

Interpretation Guide

At curve point P=0.5, "the least-served half holds only L share of value." A(1)=0.25: society could give up 25% of value and if equally shared be no worse off. Exploding Atkinson across ε: if A goes from 0.15 at ε=0.5 to 0.65 at ε=2, pain is concentrated in the very bottom tail.

Academic References

Atkinson, A.B. (1970). "On the measurement of inequality." Journal of Economic Theory, 2(3), 244–263. DOI: 10.1016/0022-0531(70)90039-6 ✓✓✓

Demographic Equity Cross-Tabs

Processing ID: planx:equitycrosstab

Overview

Cross-tabulates a per-unit value by population subgroup. Value axis divided into population-weighted quantile classes (quintiles default). For every group × class: representation ratio (group's class share / group's population share). 1 = proportional; >1 in lowest class = disadvantaged. Per group: population share, value share, mean, P10/median/P90, within-group Gini, and Duncan & Duncan dissimilarity index vs. the rest.

Interpretation Guide

Go straight to class 1 (worst-served quintile): any group with rep_ratio >1.5 carries disproportionate deprivation. Dissimilarity index >0.3: nearly a third of the group would have to "move classes" to match everyone else. Map class 1 units of the over-represented group — equity findings only persuade when they become places on the map.

Academic References

Duncan, O.D. & Duncan, B. (1955). "A methodological analysis of segregation indexes." American Sociological Review, 20(2), 210–217. DOI: 10.2307/2088328 ✓✓✓

Computes scheduled service intensity per stop within a time window on a single service day. Output: departure count, per-hour frequency, mean headway (window / departures), and distinct route count. Morning peak (07:00–09:00) is the classic window for frequent-network mapping.

Mathematical Formulation

$\text{per\_hour}_s = \text{departures}_s / \Delta t$, $\text{headway\_min}_s = (t_{end}-t_{start}) / (60 \cdot \text{departures}_s)$ (window-mean, not gap distribution).

Interpretation Guide

6+ departures/hour = "turn-up-and-go" frequent network — riders stop checking timetables. At 15–20 min, riders plan around the timetable. Compare peak vs. midday: a station dropping from 8/hour to 1/hour serves commuters only. Housing intensification should be tested against this output — "transit-served" backed only by stop presence (not frequency) is misleading.

Academic References

Walker, J. (2012). Human Transit. Island Press. [no DOI]

Transit Travel-Time Access

Processing ID: planx:transitaccess

Overview

Door-to-door travel times from origins to destinations using walking on street network + transit riding on a GTFS timetable. RAPTOR-style earliest-arrival algorithm (Delling et al., 2015): boards the first catchable trip, propagates arrivals along route patterns, up to N re-boardings. Walking legs before (access) and after (egress) via multi-source Dijkstra. Output: walk_min, transit_min, best_min, saved_min, mode.

Interpretation Guide

saved_min is transit's value proposition per destination. Near zero at >5 km = damning. transit_min includes waiting for the first catchable trip: a destination at 15 min at 08:00 and 40 min at 10:00 is frequency-failing. "mode = Walk" everywhere near a rail line usually = access walk bottleneck. Sweep departure hours to expose peak vs. all-day differences.

Academic References

Delling, D., Pajor, T., & Werneck, R.F. (2015). "Round-Based Public Transit Routing." Transportation Science, 49(3), 591–604. DOI: 10.1287/trsc.2014.0534 ✓✓✓

12. Visibility

Viewshed (DSM)

Processing ID: planx:viewshed

Overview

Computes visibility-count raster from observer points over a DSM. Azimuth rays at half-pixel intervals carry a running horizon angle outward; a target cell is visible when the slope to its surface + target height clears the accumulated horizon (Fisher, 1993). Output: integer count of observers seeing each cell.

Interpretation Guide

With one observer: binary truth map (1 = unobstructed sight line). With multiple: coverage redundancy. Observer height answers "what do I see"; target height answers "can a person there be seen." For CCTV/lighting audits: map 0-count cells along pedestrian routes. For visual impact: place observers at protected viewpoints, test proposed massing cells.

Academic References

Fisher, P.F. (1993). "Algorithm and implementation uncertainty in viewshed analysis." IJGIS, 7(4), 331–347. DOI: 10.1080/02693799308901965 ✓✓✓

Isovist Field

Processing ID: planx:isovistfield

Overview

Samples a point grid over open space and computes isovist measures per point: area, perimeter, min/max/mean radial length, circularity ($4\pi A/P^2$), and occlusivity (share of rays blocked by buildings vs. distance/edge). Based on Benedikt (1979). Buildings rasterised to obstacle grid; rays march outward until blocked or max distance reached.

Interpretation Guide

iso_area captures perceived spaciousness — its gradient is spatial drama (narrow street opening onto plaza registers as a sudden jump). circular separates space types: high = rooms/plazas (gathering), low with high max_rad = corridors/vistas (movement). min_rad measures intimacy. occlus distinguishes "enclosed by buildings" (urban rooms) from "limited by distance" (open field).

Academic References

Benedikt, M.L. (1979). "To Take Hold of Space: Isovists and Isovist Fields." Environment and Planning B, 6(1), 47–65. DOI: 10.1068/b060047 ✓✓✓

Visual Exposure of Landmarks

Processing ID: planx:visualexposure

Overview

Inverse viewshed: from where can a landmark be seen? Samples landmark polygon boundary points, sweeps a viewshed from each (treating the landmark as observer at DSM + extra height), and counts how many sample points each cell can see. High counts = full silhouette visible; low counts = glimpses; zero = hidden. The standard input for skyline and heritage impact assessment.

Interpretation Guide

Count as silhouette completeness: near-maximum sample points = postcard views; mid-counts = partial; 1–2 = glimpses. High-count corridors radiating along street axes = classic "view cones" that heritage plans protect through height restrictions. Before/after DSM differencing: insert proposed massing, rerun, difference the rasters. Every cell that loses visibility is the heritage-impact exhibit.

Academic References

Fisher, P.F. (1996). "Extending the applicability of viewsheds in landscape planning." Photogrammetric Engineering & Remote Sensing, 62(11), 1297–1302. [no DOI]

13. Population and Housing

Population Projection (Cohort-Component)

Processing ID: planx:populationprojection

Overview

Projects an age-structured population forward using the Leslie (1945) matrix: first-row fertility, sub-diagonal survival, last diagonal keeps open-ended group, net migration added after each step. Single-sex (total population). Rates stay constant — a "what current trends imply" projection, not a forecast.

Mathematical Formulation

$n_{t+1} = \max(0, L \cdot n_t + m)$ where $L$ is the $k \times k$ Leslie matrix with $f_a$ on row 0, $s_a$ on sub-diagonal, $s_{k-1}$ on bottom-right diagonal.

Interpretation Guide

Age structure at the horizon matters more than the total. A flat total can conceal a school-age bulge arriving in step 2 or an over-65 wave. Constant rates make this a "current trends" projection. Run low/mid/high migration variants and plan to the range, not the line. The horizon total feeds Housing Needs Assessment.

Academic References

Leslie, P.H. (1945). "On the Use of Matrices in Certain Population Mathematics." Biometrika, 33(3), 183–212. DOI: 10.1093/biomet/33.3.183 ✓✓✓

Housing Needs Assessment

Processing ID: planx:housingneeds

Overview

Computes additional dwellings needed by the horizon year: horizon population ÷ household size → households, × (1 + vacancy) → target stock, − existing stock + losses + backlog → need. Every intermediate calculation is output for full auditability.

Mathematical Formulation

$\text{need} = P_{future} / \text{hh\_size} \times (1+v) - D_{existing} + R_{losses} + B_{backlog}$.

Interpretation Guide

Household size is the dominant lever: a 0.2 drop can generate more need than a decade of population growth. Zero backlog and zero replacement almost always understate real need. A surplus coinciding with housing stress = type/price/location mismatch. Run household-size sensitivities (2.8, 2.5, 2.2). Compare against Residential Capacity — if capacity < need, the plan must upzone, expand, or challenge assumptions.

Academic References

Liu, J., Daily, G.C., Ehrlich, P.R., & Luck, G.W. (2003). "Effects of household dynamics on resource consumption." Nature, 421, 530–533. DOI: 10.1038/nature01359 ✓✓✓

Residential Capacity

Processing ID: planx:residentialcapacity

Overview

Computes remaining dwelling-unit capacity per parcel under current zoning: $\text{units} = \lfloor \max(0, \text{area} \cdot \text{FAR} - \text{existing}) \times e / u \rfloor$. Flooring is deliberately conservative (fractional units don't exist). Output: parcel capacity and optional district roll-up.

Interpretation Guide

Total is theoretical zoning capacity — what rules allow, not what the market builds. Standard practice discounts 50–70% over a plan horizon. Capacity concentrated in few large parcels is fragile (one landowner stalls the plan). Capacity spread as 1 unit/plot across old fabric mostly never materialises. Compare district roll-up against Housing Needs — the gap sizes the upzoning/expansion decision.

Academic References

Bibby, P., Henneberry, J., & Halleux, J.-M. (2020). "Under the radar? 'Soft' residential densification." EPB: Urban Analytics, 47(1), 102–118. DOI: 10.1177/2399808318772842 ✓✓✓

Allocate Population Growth

Processing ID: planx:popallocate

Overview

Distributes a population increment across parcels using largest-remainder apportionment (Hare-Niemeyer): floor quotas assigned first, remaining units distributed one-by-one to largest fractional remainders. Guarantees exact summation. Weights from capacity field, custom field, or uniform.

Interpretation Guide

allocated is a bookkeeping distribution, not a forecast. Determinism = same inputs, same allocation — differences between scenarios come only from weight changes. Zero-weight parcels get nothing by design. Add allocated to current baseline for the horizon-year distribution that all demand-driven tools consume.

14. Green Infrastructure

Green Space Access

Processing ID: planx:greenaccess

Overview

Evaluates whether every demand point can reach green spaces of different size classes within network distance defined by a park hierarchy (e.g. 0.5=300, 2=800, 10=2000 — min hectares = max metres). Multi-source Dijkstra from qualifying greens with snap offsets. Output: per-class distance and ok flag, classes met count, and population-coverage summary per class.

Interpretation Guide

The summary's coverage share per class is the scorecard. Most cities pass the pocket-park test and fail district-park: greenery is fragmented. Points with classes_met=0 are true green deserts. Green per capita (log) and access can disagree: a city can be "green" while greenery sits where nobody lives. Where distance fails but a qualifying park lies just beyond a barrier, the remedy is a pedestrian crossing, not a new park.

Academic References

Higgs, G., Fry, R., & Langford, M. (2012). "Investigating the implications of using alternative GIS-based techniques to measure accessibility to green space." Environment and Planning B, 39(2), 326–343. DOI: 10.1068/b37130 ✓✓✓

Urban Green Connectivity

Processing ID: planx:greenconnectivity

Overview

Evaluates the green network as a connected system. Two patches linked when edge-to-edge gap ≤ max distance. Binary Probability of Connectivity (Saura & Pascual-Hortal, 2007): $PC = \sum_c (\sum_{i \in c} a_i)^2 / (\sum a_i)^2$. Per-patch importance: $dPC_i = 100 \cdot (PC - PC^{-i})/PC$ — the share of PC lost if the patch is removed.

Interpretation Guide

dPC is the protection-priority list — highest dPC = loss most fragments the network. The planning surprise: a small stepping-stone patch with disproportionately large dPC, bridging two large components. PC is scenario currency: compare "new 2-ha park" against "0.2-ha stepping stone" — the stone often wins on connectivity grounds. Overlay high-dPC patches on development-pressure maps to find land-use conflicts worth contesting.

Academic References

Saura, S. & Pascual-Hortal, L. (2007). "A new habitat availability index." Landscape and Urban Planning, 83(2–3), 91–103. DOI: 10.1016/j.landurbplan.2007.03.005 ✓✓✓

15. Urban Growth

Land-Cover Change Analysis

Processing ID: planx:landcoverchange

Overview

Cross-tabulates two integer-class rasters cell-by-cell to produce the classic transition matrix (from-class × to-class with cell count and hectares) and per-class summary (t1 area, t2 area, persistence, gains, losses, net change). Diagonal = persistence; off-diagonal = conversions. The log names the single largest conversion — typically the headline finding.

Mathematical Formulation

$M_{a,b} = |\{(r,c): L_1[r,c]=c_a \land L_2[r,c]=c_b\}|$. $\text{net}_a = \text{gained}_a - \text{lost}_a$. Area: $\text{area\_ha} = \text{cells} \times \text{pixel}^2 / 10000$.

Interpretation Guide

Read the matrix by its biggest off-diagonal cells — those are the actual land conversions. In the summary: classes with large gains AND losses but near-zero net = spatial displacement, fundamentally different from simple loss. Impossible transitions (water→forest in 5 years) are usually classification error — their share approximates the data's noise floor.

Academic References

Pontius, R.G., Shusas, E., & McEachern, M. (2004). "Detecting important categorical land changes." Agriculture, Ecosystems & Environment, 101(2–3), 251–268. DOI: 10.1016/j.agee.2003.09.008 ✓✓✓

Urban Growth Simulation (CA)

Processing ID: planx:growthsim

Overview

Constrained cellular automaton in the SLEUTH tradition (Clarke & Gaydos, 1998). Each step: non-urban, unconstrained cells scored as $\text{suit} \cdot (\beta + w \cdot N_{urban}) + \epsilon$, top-k convert to urban until step's land-demand allotment fulfilled. Fully deterministic (seeded tie-breaking jitter of order $10^{-9}$). Output: year-of-conversion raster (0 = initial urban, 1,2,… = step, -1 = never).

Interpretation Guide

This is a WHERE model, not a WHEN forecast. Demand in hectares sets how much land converts; the model chooses where. Step numbers = sequence, not calendar years. Overlay converted cells on farmland, flood zones, planned green wedges: "the trend consumes X ha of the green wedge by step 4" justifies a development constraint. Run trend (no constraints) vs. plan (with constraints), identical demand — difference shows what the plan must resist and where displaced growth lands.

Academic References

Clarke, K.C. & Gaydos, L.J. (1998). "Loose-coupling a cellular automaton model and GIS." IJGIS, 12(7), 699–714. DOI: 10.1080/136588198241617 ✓✓✓

Urban Sprawl Metrics

Processing ID: planx:sprawlmetrics

Overview

Computes SDG Indicator 11.3.1 — the Land Consumption Rate to Population Growth Rate ratio — plus shape metrics: patch count, largest-patch share, and edge density. Input: two binary urban-extent rasters and two population figures.

Mathematical Formulation

$\text{LCR} = \ln(U_2/U_1)$, $\text{PGR} = \ln(P_2/P_1)$, $\text{LCRPGR} = \text{LCR}/\text{PGR}$ (NaN if PGR=0). Edge density: $\text{edge\_density} = \text{edge\_length} \times \text{pixel} / U_2$.

Interpretation Guide

LCRPGR ~1.0: land and people grow in step. 1.5–2.0: common sprawl range. <1.0: densification. With near-zero population growth, ratio becomes unstable — always report LCR and PGR alongside. Rising patch count + falling largest-patch share = leapfrog fragmentation. Rising edge density at stable patch count = ragged-edge growth. Both trends healthy = compact extension.

Academic References

UN-Habitat (2018). SDG Indicator 11.3.1 — Metadata. [no DOI]

Schwarz, N. (2010). "Urban form revisited." Landscape and Urban Planning, 96(1), 29–47. DOI: 10.1016/j.landurbplan.2010.01.007 ✓✓✓

16. Cycling

Cycling Stress (LTS)

Processing ID: planx:cyclingstress

Overview

Classifies every street segment LTS 1–4 using a simplified Mekuria/Furth screening rule. Three infrastructure regimes: separated paths → LTS 1; painted lanes → LTS 2/3 based on speed and lanes; mixed traffic → LTS 1–4 based on speed, lanes, and AADT. All thresholds editable as key=value text. Output: LTS class, label, segment length, and attribute values actually used.

Interpretation Guide

LTS 1–2 share = the "all-ages network." LTS 4 share >20% = network hostile to everyday cycling. Long continuous LTS 1–2 corridors severed by short LTS 4 gaps = the highest-value interventions. A school on an LTS 4 arterial is a priority project. Run before/after editing the infrastructure field to simulate a protected lane.

Academic References

Mekuria, M.C., Furth, P.G., & Nixon, H. (2012). Low-Stress Bicycling and Network Connectivity. Mineta Transportation Institute. [no DOI]

Low-Stress Connectivity

Processing ID: planx:lowstressislands

Overview

Drops all segments above a chosen LTS threshold and finds connected cycling "islands" via depth-first search on the remaining primal graph. High-stress segments preserved with island_id=0 as barriers. Optional population reachability: snaps origins and destinations to network, reports the share of population in islands that contain at least one destination.

Interpretation Guide

Many small islands + one dominant = fragmented network. Gaps between islands (id-0 edges) = priority intervention list — each gap separating two large islands is a candidate for a protected crossing. Island_id=0 everywhere = threshold too low or broken topology. Population reach KPI is policy-ready: "X% of residents can reach a school at LTS 2." Track across scenarios — the KPI jumps when a strategic gap closes.

17. Hazard Screening

Flow Accumulation

Processing ID: planx:flowaccumulation

Overview

Three foundational hydrological rasters from a DEM: depression-filled DEM (Wang & Liu, 2006 priority-flood), D8 steepest-descent flow direction (Jenson & Domingue, 1988), and topological flow accumulation via Kahn's algorithm. The plumbing for HAND Index and Flood Exposure.

Mathematical Formulation

D8 slope: $\text{slope}(dr,dc) = (Z(r,c)-Z(r+dr,c+dc)) / \text{dist}(dr,dc)$, with dist=1 for cardinal, √2 for diagonal. Flow direction code = steepest positive slope neighbour (E=1, SE=2, S=4, SW=8, W=16, NW=32, N=64, NE=128, 0=flat). Accumulation: topological sort on reverse graph: $A(nr,nc) += A(r,c)$.

Interpretation Guide

High accumulation = flow concentration zones. In urban areas, high-accumulation lines crossing streets = surface flow paths during cloudbursts. Buildings on high-accumulation lines = elevated pluvial flood risk. Filled minus original DEM: depressions >0.5 m in urban fabric = pluvial ponding locations. Threshold accumulation at top 1% for synthetic stream network.

Academic References

Wang, L. & Liu, H. (2006). "An efficient method for identifying and filling surface depressions." IJGIS, 20(2), 193–213. DOI: 10.1080/13658810500433453 ✓✓✓

Jenson, S.K. & Domingue, J.O. (1988). "Extracting topographic structure." PE&RS, 54(11), 1593–1600. [no DOI]

HAND and Inundation

Processing ID: planx:handindex

Overview

Height Above Nearest Drainage: vertical distance from each cell to the nearest drainage cell (flow accumulation ≥ threshold) traced along the D8 flow path (Renno et al., 2008). Then bathtub inundation mask: all cells with HAND ≤ depth. HAND is a hydrologically meaningful normalisation: unlike raw elevation, it measures local draining potential.

Mathematical Formulation

$\text{HAND}(r,c) = Z(r,c) - Z(d_r, d_c)$ where $(d_r,d_c)$ is the terminal drainage cell downstream. Inundation: $\mathbf{1}[\text{HAND}(r,c) \leq \text{depth}]$.

Interpretation Guide

HAND <1 m = floodplain by construction. 1–2 m = high exposure. 2–5 m = moderate. >10 m = flood-safe for planning. Run at multiple depths (0.5, 1, 2, 5 m). Scattered wet cells away from streams = pluvial ponding locations. Plot the curve of exposed population vs. depth. Threshold scales with cell area: target 0.1–1 km² drainage area.

Academic References

Renno, C.D., et al. (2008). "HAND, a new terrain descriptor using SRTM-DEM." Remote Sensing of Environment, 112(9), 3469–3481. DOI: 10.1016/j.rse.2008.03.018 ✓✓✓

Flood Exposure

Processing ID: planx:floodexposure

Overview

Intersects a binary inundation mask with building centroids and/or population-weighted demand points. Outputs a one-row summary: exposed buildings (count + %), exposed population (count + %), and optional annotated demand points with wet/dry status. Run once per depth scenario to build up the exposure curve.

Interpretation Guide

Plot pct_pop vs. depth: flat-then-sharp rise = city above floodplain; steady rise = city sprawls into floodplain; explosive 1–2 m = creeping risk. Compare existing vs. proposed development: if proposed has higher exposure, the plan is manufacturing tomorrow's risk. Salt-and-pepper wet points = drainage network problem (pluvial signature), not a single river.

18. Travel Demand

Trip Generation

Processing ID: planx:tripgeneration

Overview

Step 1 of the four-step travel demand model. Linear trip generation: $P_i = p_i \cdot r_P$, $A_i = j_i \cdot r_A$. Productions = resident trips generated; Attractions = jobs pulling trips in. P/A ratio per zone is a land-use diagnosis: P≫A = dormitory; A≫P = employment core; P~A = balanced.

Interpretation Guide

P/A imbalance map alone often suffices for a land-use diagnosis. A large imbalance signals the study area boundary cuts through commuting sheds — expand the area or add external zones. Default rates (P=1.5/cap, A=2.0/job) are order-of-magnitude starting values; calibrate against local surveys for consequential analysis.

Academic References

Ortúzar, J. de D. & Willumsen, L.G. (2011). Modelling Transport (4th ed.). Wiley. DOI: 10.1002/9781119993308 ✓✓✓

Gravity Distribution

Processing ID: planx:gravitymodel

Overview

Step 2: doubly constrained (Furness/IPF) gravity model over network-computed cost matrix. Deterrence: exponential $\exp(-\beta c)$ or power $c^{-\beta}$. Iterates row/column balancing until convergence or max_iter. Output: OD flow table and optional desire lines.

Mathematical Formulation

$T_{ij}^{(k)} = r_i^{(k)} \cdot F_{ij} \cdot s_j^{(k)}$ where $F_{ij} = \exp(-\beta c_{ij})$ or $c_{ij}^{-\beta}$. Row: $r_i = P_i / \sum_j F_{ij} s_j$. Column: $s_j = A_j / \sum_i F_{ij} r_i$. Convergence: $\max(|\sum_j T_{ij} - P_i|, |\sum_i T_{ij} - A_j|) < \text{tol}$.

Interpretation Guide

Top 10 flows are the dominant corridors — where the land-use plan silently orders transport capacity. Beta controls trip-length behaviour: higher = shorter trips. Calibrate so modelled mean trip cost matches observed. Run with 3 beta values — the spread is uncertainty. Difference two OD tables (base vs. plan): cells with large flow increases signal corridors under growth pressure.

Academic References

Wilson, A.G. (1967). "A statistical theory of spatial distribution models." Transportation Research, 1(3), 253–269. DOI: 10.1016/0041-1647(67)90035-4 ✓✓✓

Mode Split

Processing ID: planx:modesplit

Overview

Step 3: multinomial logit mode choice (McFadden, 1974). For each OD pair: $V_k = \text{ASC}_k + \beta_k \cdot t_k$, $P_k = \exp(V_k) / \sum_m \exp(V_m)$, $F_k = P_k \cdot F_{total}$. Log-sum-exp stabilisation prevents overflow.

Interpretation Guide

With uncalibrated ASCs, absolute shares are indicative — the robust finding is the DIFFERENCE between scenarios. "The bus lane shifts 340 daily trips from car to transit" is defensible; "transit share = 23%" is not (without calibration). Beta of -0.1: each minute of travel time multiplies odds by ~0.905. ASC captures unmeasured factors (comfort, flexibility, habit).

Academic References

McFadden, D. (1974). "Conditional logit analysis of qualitative choice behavior." In Zarembka (ed.), Frontiers in Econometrics, 105–142. [no DOI]

Train, K.E. (2009). Discrete Choice Methods with Simulation (2nd ed.). Cambridge. DOI: 10.1017/CBO9780511805271 ✓✓✓

19. Seismic Risk

Seismic Collapse and Debris Spread (Monte Carlo)

Processing ID: planx:seismicdebris

Overview

Screening-quality Monte Carlo model for earthquake-induced building collapse, road-blocking debris, and evacuation corridor identification. For each building: collapse probability from construction-year vulnerability tier scaled by $\exp(0.8(M_w - 7.0))$. Single seeded draw determines collapse. Collapsed buildings spread debris to $r = k \cdot H$ (Goretti & Sarli, 2006), volume $V = A \cdot H \cdot \eta$. Four alternative road-network definitions.

Mathematical Formulation

Collapse probability: $p_i = \min(1, \max(0, p_{base}(y_i) \cdot \exp(0.8(M_w-7.0))))$, where $p_{base} = 0.85$ (≤1985), 0.60 (≤2000), 0.25 (≤2018), 0.05 (later). Debris radius: $r_i = k \cdot n_i \cdot h$ if collapsed, else 0. Debris volume: $V_i = A_i \cdot H_i \cdot \eta$ if collapsed.

Interpretation Guide

One run = one realisation. The collapsed flag is a single dice roll — the p_collapse field is the stable diagnostic. Run 10–20 seeds; corridors that survive EVERY run = dependable evacuation skeleton. Overlay open corridors on hospitals/fire stations — a facility with all approaches blocked in most seeds needs a second access NOW. Priority retrofit: high p_collapse × tall × abutting narrow streets. Debris volume (logged) sizes the clearance problem. Sweep Mw 6.5 → 7.5 to find the resilience cliff.

Academic References

Goretti, A. & Sarli, V. (2006). "Road network and damaged buildings in urban areas." Bulletin of Earthquake Engineering, 4(2), 159–175. DOI: 10.1007/s10518-006-9004-3 ✓✓✓

Digital Elevation Model — raster of bare-earth terrain heights.
DSM
Digital Surface Model — raster of terrain + building + vegetation heights.
Dijkstra
Shortest-path algorithm for non-negative edge weights; runs in $O((V+E)\log V)$.
dPC
Delta Probability of Connectivity — share of connectivity index lost when a patch is removed.
FAR / FSI
Floor Area Ratio / Floor Space Index — gross floor area divided by site area.
Furness / IPF
Iterative Proportional Fitting — balances matrix rows and columns to match target marginals.
Gini coefficient
Inequality measure: 0 = perfect equality, 1 = maximal inequality. Twice the area between the Lorenz curve and equality line.
GSI
Ground Space Index — building footprint area divided by site area (coverage).
GTFS
General Transit Feed Specification — standard open format for public transit schedules.
HAND
Height Above Nearest Drainage — vertical distance from a cell to the nearest stream cell along the D8 flow path.
Hare-Niemeyer
Largest-remainder apportionment method — guarantees exact integer allocation summing to the target.
Isovist
The set of all points visible from a given vantage point (Benedikt, 1979).
LCRPGR
Land Consumption Rate to Population Growth Rate ratio — SDG Indicator 11.3.1.
Leslie matrix
Age-structured population projection matrix: fertility on first row, survival on sub-diagonal.
Lorenz curve
Plot of cumulative population share vs. cumulative value share — graphical inequality measure.
LTS
Level of Traffic Stress — 1 (children) to 4 (strong and fearless only), for cycling.
MCLP
Maximal Covering Location Problem — maximise population served within a distance given p facilities.
MNL
Multinomial Logit — discrete choice model with Gumbel-distributed errors (McFadden, 1974).
NAIN
Normalised Angular INtegration — size-independent to-movement potential (Hillier, Yang & Turner, 2012).
NACH
Normalised Angular CHoice — size-independent through-movement potential.
OSR
Open Space Ratio — (1 − GSI) / FSI; spaciousness.
PC (connectivity)
Probability of Connectivity — sum of squared component areas divided by total area squared.
Pedshed ratio
Network catchment area divided by straight-line circle area — measures street-layout efficiency.
P-median
Facility location problem: minimise population-weighted total travel distance with p facilities.
RAPTOR
Round-based Public Transit Routing — earliest-arrival algorithm using timetable rounds.
SVF
Sky View Factor — fraction of visible sky hemisphere from a point (0–1).
Tobler function
Walking speed as a function of slope: $v = 6 \cdot e^{-3.5|m+0.05|}$ km/h.
Theil index
Inequality measure from information theory; additively decomposable into between/within groups.
UTM
Universal Transverse Mercator — projected CRS family in metres, suitable for all PlanX tools.
λf / λp
Frontal Area Index ($\lambda_f$) and Plan Area Index ($\lambda_p$) — urban roughness parameters.
